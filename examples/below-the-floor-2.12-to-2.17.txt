Worked example output: glibc-2.12 -> glibc-2.17

NOT AN AUDITED PAIR, and not a published verdict. This project audits
RHEL8 -> RHEL9 and RHEL9 -> RHEL10; neither side here is a system anyone should
be running. It is kept for one reason: this pair sits below the OLD glibc 2.24
version floor, and it is what showed that floor was a bug in one function
rather than something the method structurally could not do.

See ../docs/limitations.md, "Below glibc 2.24 the method rests on one measured
pair" -- this file is that pair.

Both sides below are real runs of ./audit.sh glibc-2.12 glibc-2.17, against
glibc-2.12 = e28c88707ef0 and glibc-2.17 = c758a6861537, the commits pinned in
tests/_harness.py. "BEFORE" is the code as of the sixteenth CHANGELOG entry;
"AFTER" is with collate_block built on collate_bounds instead of a regex that
could not read a block starting at byte 0.

                                            BEFORE     AFTER
  Step 3, affected locale source files          11       278
  Step 4, needing empirical confirmation       277       279
  Step 4, generated names per SUPPORTED        404       408

The three files the bug dropped are iso14651_t1, iso14651_t1_common and
iso14651_t1_pinyin -- in glibc 2.23 and earlier they open with LC_COLLATE on
the very first byte. They are the highest fan-in files in the corpus, so
losing them as graph nodes made everything inheriting from them look
unaffected.

These numbers are asserted in tests/test_known_answers.py
(BelowTheOldVersionFloor). The figure this page's predecessor carried for step 4
was 2, and it had been wrong for some time before anyone re-ran it; a number
nothing tests is a number that rots.

Step 5 is not reproduced here. It prints 65 hunks over this pair and decides
none of them, which is the fifth limitation rather than this one.

Long comma-separated name lists below are trimmed, marked where cut.
